# 从零构建一个 AI 聊天应用（保姆级教程）

> **配套代码**：本仓库 `chat-demo/` —— TypeScript + `@tencent-ai/agent-sdk` + Express + WebSocket + React
> **你会学到**：SDK 流式输出如何接入服务端、WebSocket 如何把「思考过程 + 回答」实时推给前端、多会话如何管理、断线如何恢复。
> **日期**：2026-09-04

## 太长不看（TL;DR）

本教程带你搭一个**能选会话、能发消息、能实时看到智能体「正在调用什么工具」**的聊天 Web 应用。全部代码在本仓库 `chat-demo/`，跟着下面的步骤，你就是「抄一遍」也能学会架构。

核心链路只有一句：

```text
React ──WS──► Express/WebSocket 服务 ──► ChatSession（一个会话一个智能体）
                                            │
                        @tencent-ai/agent-sdk 的 query() 异步流
                                            │
                拆成 user/assistant/tool_use/result 事件广播回浏览器
```

## 第一步：集中配置 `server/config.ts`

所有「以后可能要调」的东西集中一处，后面代码里不要再出现魔法数字：

```ts

  server: {

    port: parseInt(process.env.PORT || '4001', 10),
    wsPath: '/ws',
  },
  chat: {
    maxMessagesPerChat: 100,   // 每个会话最多保留多少条消息
    maxChats: 50,              // 内存最多保留多少会话（超出淘汰最旧的）
    defaultTitle: '新对话',
    titleMaxLength: 50,
  },
  agent: {
    // model: 'claude-opus-4.5' as const, // 不指定模型，使用默认配置
    maxTurns: 1,              // 想真正跑工具循环，建议调大到 20~50
    allowedTools: ['Bash', 'Read', 'Write', 'Edit', 'Glob', 'Grep', 'WebSearch', 'WebFetch'],
  },
  websocket: {
    heartbeatInterval: 30000, // 心跳间隔，用于探测死连接
```

## 第二步：把 SDK 包成 `Agent` 类

我们不希望业务代码到处 `query()`，于是做一个薄封装：**发一条消息 = 启动一个新的异步流**，外部通过 `getOutputStream()` 消费。

```ts
// chat-demo/server/agent.ts
import { query } from "@tencent-ai/agent-sdk";
import { config } from "./config.js";

const SYSTEM_PROMPT = `你是一个乐于助人的 AI 助手。你可以帮助用户完成各种任务，包括：
- 回答问题
- 撰写和编辑文本
- 编程和调试代码
- 分析和研究
- 创意任务
请保持回复简洁但全面。`;

export class Agent {
  private currentStream: AsyncIterator<any> | null = null;

  async sendMessage(content: string) {
    // query() 返回异步生成器：assistant / tool_use / result 依次流出
    this.currentStream = query({
      prompt: content,
      options: {
        maxTurns: config.agent.maxTurns,
        cwd: process.cwd(),
        executable: "node",
        allowedTools: [...config.agent.allowedTools],
        systemPrompt: SYSTEM_PROMPT,
      },
    })[Symbol.asyncIterator]();
  }

  async *getOutputStream() {
    if (!this.currentStream) throw new Error("No active stream. Call sendMessage() first.");
    while (true) {
      const { value, done } = await this.currentStream.next();
      if (done) { this.currentStream = null; break; }
      yield value;
    }
  }

  close() { this.currentStream = null; }
}
```

要点：`query()` 的 options 里我们**不传模型**（注释：不指定模型，使用默认配置），继承环境里 CodeBuddy 的默认模型；`cwd` 指向进程目录，让 `Read`/`Write` 等工具有明确的工作基地。

## 第三步：内存存储 `store.ts`（含自动清理）

原型阶段没必要上数据库。这个 store 有两个「保鲜机制」：**每个会话最多 100 条消息**（超出丢掉最旧的），**最多 50 个会话**（超出按更新时间淘汰最旧，即简易 LRU）。另外，第一条用户消息会自动变成会话标题。

```ts
  deleteChat(id): boolean       { /* 同时删 messages */ }

  addMessage(chatId, message) {

    // 标题仍是"新对话"且是用户消息 → 用首条消息生成标题（超长截断 + "..."）
```

## 第四步：`ChatSession`——一个会话就是一个小型「消息中心」

这是全项目最有价值的一段设计。每个会话持有一个 `Agent` 和一组 WebSocket 订阅者：

- 用户发消息 → 存库 + 广播 `user_message` → 交给 Agent；
- Agent 的异步流里每冒出一条消息，就**转发给所有订阅者**（多端同屏的关键）；
- 把 SDK 的消息翻译成前端友好的事件。

```ts
// chat-demo/server/chat-session.ts（核心逻辑）
export class ChatSession {
  public readonly chatId: string;
  private subscribers: Set<WSClient> = new Set();
  private agent = new Agent();
  private isListening = false;

  async sendMessage(content: string) {
    chatStore.addMessage(this.chatId, { role: "user", content });
    this.broadcast({ type: "user_message", content, chatId: this.chatId });

    await this.agent.sendMessage(content);   // 启动新流
    if (!this.isListening) this.startListening(); // 同一时间只挂一个消费者
  }

  private async startListening() {
    if (this.isListening) return;
    this.isListening = true;
    try {
      for await (const message of this.agent.getOutputStream()) {
        this.handleSDKMessage(message);      // ← 翻译 + 广播
      }
    } catch (error) {
      this.broadcastError((error as Error).message);
    } finally {
      this.isListening = false;              // 流结束复位，可接下一轮
    }
  }

  private handleSDKMessage(message: any) {
    if (message.type === "assistant") {
      const content = message.message.content;
      if (typeof content === "string") {
        // 纯文本
        chatStore.addMessage(this.chatId, { role: "assistant", content });
        this.broadcast({ type: "assistant_message", content, chatId: this.chatId });
      } else if (Array.isArray(content)) {
        for (const block of content) {
          if (block.type === "text") {        // 文本块
            chatStore.addMessage(this.chatId, { role: "assistant", content: block.text });
            this.broadcast({ type: "assistant_message", content: block.text, chatId: this.chatId });
          } else if (block.type === "tool_use") { // 模型要调用工具 → 单独事件
            this.broadcast({ type: "tool_use", toolName: block.name,
                             toolId: block.id, toolInput: block.input, chatId: this.chatId });
          }
        }
      }
    } else if (message.type === "result") {
      // 本轮结束：带成功与否 + 费用 + 耗时
      this.broadcast({ type: "result", success: message.subtype === "success",
                       chatId: this.chatId, cost: message.total_cost_usd,
                       duration: message.duration_ms });
    }
  }

  subscribe(client: WSClient)   { this.subscribers.add(client); client.sessionId = this.chatId; }
  unsubscribe(client: WSClient) { this.subscribers.delete(client); }
  hasSubscribers(): boolean     { return this.subscribers.size > 0; }

  private broadcast(message: any) {
    const messageStr = JSON.stringify(message);
    for (const client of this.subscribers) {
      if (client.readyState === client.OPEN) client.send(messageStr);
    }
  }
}
```

## 第五步：把会话挂到服务上 `server.ts`

HTTP 管「会话 CRUD」，WebSocket 管「实时消息」。`sessions` Map 负责把 `chatId` 映射到 `ChatSession`（惰性创建）。

```ts
// chat-demo/server/server.ts（摘录）
const sessions: Map<string, ChatSession> = new Map();
function getOrCreateSession(chatId: string): ChatSession {
  let session = sessions.get(chatId);
  if (!session) { session = new ChatSession(chatId); sessions.set(chatId, session); }
  return session;
}

// —— REST 层：会话列表 / 创建 / 详情 / 删除 / 历史消息 ——
app.get("/api/chats",        (req, res) => res.json(chatStore.getAllChats()));
app.post("/api/chats",       (req, res) => { /* createChat(req.body?.title) */ });
app.get("/api/chats/:id",    (req, res) => { /* getChat */ });
app.delete("/api/chats/:id", (req, res) => {
  /* 删除会话时同步 close() 并移出 sessions，防止幽灵会话 */
});
app.get("/api/chats/:id/messages", (req, res) => res.json(chatStore.getMessages(req.params.id)));

// —— WebSocket 层 ——
const wss = new WebSocketServer({ server, path: WS_PATH });
wss.on("connection", (ws: WSClient) => {
  ws.send(JSON.stringify({ type: "connected", message: "Connected to chat server" }));
  ws.isAlive = true;
  ws.on("pong", () => { ws.isAlive = true; });   // 心跳响应

  ws.on("message", async (data) => {
    const message: IncomingWSMessage = JSON.parse(data.toString());
    switch (message.type) {
      case "subscribe": {                        // ① 订阅会话
        const session = getOrCreateSession(message.chatId);
        session.subscribe(ws);
        // 立即回放历史消息，让新打开的页面无缝续聊
        ws.send(JSON.stringify({ type: "history", messages: chatStore.getMessages(message.chatId),
                                 chatId: message.chatId }));
        break;
      }
      case "chat": {                             // ② 发消息
        const session = getOrCreateSession(message.chatId);
        session.subscribe(ws);                   // 自动订阅，防漏消息
        await session.sendMessage(message.content);
        break;
      }
    }
  });

  ws.on("close", () => {
    for (const session of sessions.values()) session.unsubscribe(ws); // 全量退订
  });
});

// —— 心跳：30s 一次 ping，无 pong 的客户端直接 terminate ——
const heartbeat = setInterval(() => {
  wss.clients.forEach((ws: WSClient) => {
    if (ws.isAlive === false) return ws.terminate();
    ws.isAlive = false;
    ws.ping();
  });
}, config.websocket.heartbeatInterval);
```

## 第六步：WS 协议一览（照抄这张表就够了）

**入站（浏览器 → 服务端）**

| type | payload | 含义 |
|------|---------|------|
| `subscribe` | `{ chatId }` | 订阅某个会话（服务端回 `history`） |
| `chat` | `{ chatId, content }` | 发送一条用户消息 |

**出站（服务端 → 浏览器）**

| type | payload | 含义 |
|------|---------|------|
| `connected` | `{ message }` | 连接建立 |
| `history` | `{ messages }` | 历史消息回放 |
| `user_message` | `{ chatId, content }` | 用户消息（已本地乐观渲染，前端可忽略） |
| `assistant_message` | `{ chatId, content }` | 一段助手文本（文本块拆分推送） |
| `tool_use` | `{ chatId, toolName, toolId, toolInput }` | 助手正在调用某工具（用于实时展示） |
| `result` | `{ chatId, success, cost, duration }` | 本轮结束 + 计费耗时 |
| `error` | `{ chatId, error }` | 出错 |

> 设计妙处：`tool_use` 是独立事件。于是前端可以把「搜网页 / 读文件 / 执行命令」这些过程**实时亮给用户看**——这是 Agent 聊天和普通 LLM 聊天体验上最大的分水岭。

## 第七步：前端 Hook `useMessages`

用 `react-use-websocket` 一行拿到连接与消息，核心逻辑就是一个**协议分发器**：

```ts
// chat-demo/client/hooks/useMessages.ts（摘录）
export function useMessages({ wsUrl, onRefreshChats }) {
  const [messages, setMessages] = useState<Message[]>([]);
  const [isLoading, setIsLoading] = useState(false);

  const handleWSMessage = useCallback((message: any) => {
    switch (message.type) {
      case "history":
        setMessages(message.messages || []);        // 回放历史
        break;
      case "assistant_message":                     // 追加助手回复
        setMessages((prev) => [...prev, { id: crypto.randomUUID(), role: "assistant",
                                          content: message.content, timestamp: new Date().toISOString() }]);
        setIsLoading(false);
        break;
      case "tool_use":                              // 追加工具调用卡片
        setMessages((prev) => [...prev, { id: message.toolId, role: "tool_use", content: "",
                                          toolName: message.toolName, toolInput: message.toolInput,
                                          timestamp: new Date().toISOString() }]);
        break;
      case "result":
        setIsLoading(false);                        // 本轮结束
        onRefreshChats?.();                         // 刷新会话列表（标题/时间变了）
        break;
      case "error":
        console.error("Server error:", message.error);
        setIsLoading(false);
        break;
    }
  }, [onRefreshChats]);

  const { sendJsonMessage, readyState, lastJsonMessage } = useWebSocket(wsUrl, {
    shouldReconnect: () => true,                    // 断了自动重连
    reconnectAttempts: 10,
    reconnectInterval: 3000,
  });

  const isConnected = readyState === ReadyState.OPEN;

  const subscribeToChat = useCallback((chatId: string) => {
    setMessages([]);                                // 切会话先清屏
    sendJsonMessage({ type: "subscribe", chatId }); // 服务端会回 history
  }, [sendJsonMessage]);

  const sendMessage = useCallback((chatId: string, content: string) => {
    if (!chatId || !isConnected) return false;
    setMessages((prev) => [...prev, { id: crypto.randomUUID(), role: "user", content,  // 乐观渲染
                                      timestamp: new Date().toISOString() }]);
    setIsLoading(true);
    sendJsonMessage({ type: "chat", content, chatId });
    return true;
  }, [isConnected, sendJsonMessage]);

  return { messages, isLoading, isConnected, subscribeToChat, sendMessage, clearMessages };
}
```

三个细节值得背下来：

1. **乐观渲染**：发消息瞬间先把气泡插进列表，不等服务器回包；
2. **切会话清屏 + history 回放**：`subscribeToChat` 先 `setMessages([])`，随后服务端回 `history` 自动填充，实现“换会话不丢上下文”；
3. **自动重连**：断网后 `shouldReconnect: () => true`，客户端重新订阅即可续上（对做移动端场景尤其重要）。

## 这 200 行代码教给你的四件事

1. **SDK 只干一件事**：`query()` 给你一条流。别自己写 agent 循环，消费流、翻译事件、广播给客户端即可。
2. **一个会话 = 一个 Agent + 一堆订阅者**：SDK 消息天然是「过程性」的（`tool_use` 在 `assistant` 之前到达），前端把两者都画出来，体验立刻上一个档次。
3. **存储隔离决定演进空间**：内存 Map → SQLite → Redis/Postgres，业务层不用动。
4. **协议先行**：先定下 `subscribe/chat/history/tool_use` 这套小协议，前后端就能并行开发，谁也不用等谁。
