**尺寸**：
- 宽度：280px
- 最小高度：120px
- 圆角：8px
- 内边距：16px

```
┌──────────────────────────┐

## 3. 交互规范

### 3.1 拖拽交互

**视觉反馈**：
- 拖拽时：卡片透明度 0.8，阴影增强
- 悬停在列上时：列高亮显示
- 放置预览：显示虚线框

**动画**：
- 平滑移动：0.2s ease
- 位置调整：spring animation

### 3.2 Hover 状态

**卡片 hover**：
- 阴影增强
- 更多操作按钮出现

**按钮 hover**：
- 背景色变化
- 轻微放大

### 3.3 点击交互

**点击卡片**：
- 打开详情抽屉

**点击更多**：
- 显示菜单（编辑、删除、移动）

**点击新建**：
- 打开创建弹窗（内联或弹窗）

### 3.4 空状态

**空列**：
- 显示虚线占位
- 提示文字："暂无任务，点击创建"

**无搜索结果**：
- 显示空状态插画
- 提示文字："未找到匹配的任务"

### 3.5 Loading 状态

**首次加载**：
- 显示骨架屏
- 4 列各 3 个卡片骨架

**操作中**：
- 按钮显示 loading 图标
- 禁用其他操作

# 任务看板开发任务清单（SpeckitList）

> 来源规格：
> - `feature-task-board.md`（数据模型 / API / 功能需求 / 业务规则）
> - `ui-task-board.md`（页面结构 / 组件 / 交互 / 设计系统）

## 约定说明

**优先级映射**
- `P0`：规格中明确标注 P0 的部分 —— 数据模型、API 2.1~2.4、基础功能 3.1、UI 核心组件与拖拽
- `P1`：规格中明确标注 P1 的部分 —— DELETE 接口 2.5、增强功能 3.2、体验优化 3.3
- `P2`：规格 P1 列表中可延后的可选项（自定义列、批量操作、键盘快捷键）。若团队希望严格对齐 spec，可整体上调为 P1

**工作量单位**：1 轮 = 一次完整的「需求理解 → AI 代码生成 → 自检/修复（lint、冒烟）」循环。0.5 轮 = 单点小改动。

**执行顺序**：按阶段从上到下执行（先做排最前），同阶段任务可并行。任务间的硬依赖见每项「依赖」字段。

## 阶段 1：后端 API 层（依赖 T1；如需可先以 Mock 驱动阶段 2/3）

- [ ] **T3｜GET /api/tasks 列表接口（含筛选与排序）**（P0｜1 轮）
  - 依赖：T1
  - 内容：实现 spec 2.1，支持 `status / assignee / search` 三个可选 query，并落地业务规则 2（列内排序）
  - 验收标准：
    - 响应结构为 `{ tasks: Task[] }`
    - `status` 过滤只接受合法 `TaskStatus` 值，非法值返回 400
    - `assignee` 按指派用户 id 精确过滤；`search` 匹配标题/描述关键词
    - 三参数可任意组合使用
    - 同状态内任务默认排序：`critical > high > medium > low`，同优先级按 `createdAt` 升序
    - 全部条件省略时返回全量任务

- [ ] **T4｜POST /api/tasks 创建接口**（P0｜1 轮）
  - 依赖：T1、T3
  - 内容：实现 spec 2.2，落地业务规则 3（标签限制）
  - 验收标准：
    - `title`、`priority` 必填，缺失返回 400
    - `assigneeId` 若提供则必须存在对应用户，否则 400
    - 标签校验：自动去重后数量 ≤ 5，单项长度 ≤ 20 字符，超限返回 400
    - 服务端自动生成 `id`，设置 `status = backlog`、`createdAt/updatedAt = 当前时间`
    - 响应为 `{ task: Task }`，回显字段完整
    - 可选 `dueDate` 以 ISO 日期存储

- [ ] **T5｜PATCH /api/tasks/:id 更新接口**（P0｜1 轮）
  - 依赖：T3、T4
  - 内容：实现 spec 2.3 的部分字段更新，落地业务规则 1（时间戳自动更新）
  - 验收标准：
    - 支持 `title / description / status / priority / assigneeId / tags / dueDate` 任一或组合更新
    - 标签字段被更新时同样执行 ≤5 个、≤20 字符校验
    - `status` 被置为 `done` 时，`updatedAt` 自动刷新为当前时间；其他更新同样刷新 `updatedAt`
    - 目标任务不存在返回 404；非法枚举值返回 400
    - 响应为 `{ task: Task }`

- [ ] **T6｜POST /api/tasks/:id/move 移动接口**（P0｜0.5 轮）
  - 依赖：T3、T5
  - 内容：实现 spec 2.4 的跨列移动与列内排序
  - 验收标准：
    - Body 接收 `status`（必填）与 `position?`（目标索引）
    - 跨列移动：任务状态更新为新列，并正确插入 `position` 指定位置
    - 同列移动：仅调整该任务在列内的位置
    - 目标任务不存在返回 404；`position` 越界时按边界值安全处理（不报 500）
    - 响应为 `{ task: Task }`，且后续 GET 返回的顺序与移动结果一致

- [ ] **T7｜DELETE /api/tasks/:id 删除接口**（P1｜0.5 轮）
  - 依赖：T3
  - 内容：实现 spec 2.5，落地业务规则 4
  - 验收标准：
    - 删除成功返回 `{ success: true }`
    - 已删除/不存在任务再次删除返回 404
    - 若启用「仅已完成可删除」可选规则：非 `done` 状态任务删除返回 403（规则开关需在配置中可切换）
    - 删除后 GET 列表不再返回该任务

## 阶段 3：核心交互（依赖阶段 1 API + 阶段 2 组件）

- [ ] **T12｜创建任务交互**（P0｜1 轮）
  - 依赖：T4、T9
  - 内容：实现「+ 新建任务」入口与创建弹窗（UI spec §3.3），对接 POST
  - 验收标准：
    - 点击列底或 Header「添加」按钮打开创建弹窗（弹窗圆角 12px）
    - 表单字段：标题（必填）、描述、优先级（默认 medium）、指派人、标签、截止日期
    - 标题为空或优先级缺失时给出校验提示，禁止提交
    - 标签输入限制：最多 5 个、每个 ≤20 字符，超限即时提示
    - 提交成功：关闭弹窗，新卡片出现在目标列正确排序位置；提交失败：弹窗内展示错误且保留输入

- [ ] **T13｜TaskDetailDrawer 详情抽屉与查看**（P0｜1 轮）
  - 依赖：T5、T10
  - 内容：实现 UI spec §2.6 详情抽屉（点击卡片打开）
  - 验收标准：
    - 点击卡片从右侧滑出抽屉，宽度 480px，含关闭按钮（点击 X / 遮罩 / Esc 可关闭）
    - 展示：标题、描述、状态、优先级、指派人、标签、截止日期（与 spec §2.6 结构一致）
    - 抽屉底部提供「编辑」「删除」操作位
    - 展示数据与看板卡片实时一致（同一数据源）

- [ ] **T14｜编辑任务（抽屉内编辑）**（P0｜1 轮）
  - 依赖：T5、T13
  - 内容：在详情抽屉中进入编辑态并保存（PATCH），落地状态流转规则
  - 验收标准：
    - 点击「编辑」后抽屉切换为可编辑表单，字段与创建表单一致且预填当前值
    - 可修改标题/描述/状态/优先级/指派人/标签/截止日期
    - 保存后：抽屉回到详情态，看板卡片与数量即时更新，无需整页刷新
    - 状态置为「已完成」保存成功后卡片移动至 done 列（updatedAt 已由后端刷新）
    - 保存失败时展示错误并保留编辑内容

- [ ] **T15｜拖拽移动与排序**（P0｜2 轮，最高风险项）

## 1. 数据模型

### 1.1 Task（任务）
```typescript
interface Task {
  id: string;                    // 唯一标识
  title: string;                 // 任务标题
  description?: string;          // 任务描述
  status: TaskStatus;            // 状态
  priority: Priority;            // 优先级
  assignee?: User;               // 指派人
  tags: string[];                // 标签
  dueDate?: string;              // 截止日期
  createdAt: string;             // 创建时间
  updatedAt: string;             // 更新时间
}
```

### 1.2 TaskStatus（任务状态）
```typescript
type TaskStatus =
  | 'backlog'      // 待处理
  | 'todo'         // 待办
  | 'in-progress'  // 进行中
  | 'done';        // 已完成
```

### 1.3 Priority（优先级）
```typescript
type Priority =
  | 'critical'     // 紧急
  | 'high'         // 高
  | 'medium'       // 中
  | 'low';         // 低
```

### 1.4 User（用户）
```typescript
interface User {
  id: string;
  name: string;
  avatar?: string;
}
```

## 2. API 接口

### 2.1 获取任务列表
**优先级：P0**

```
GET /api/tasks
Query Parameters:
  - status?: TaskStatus    // 按状态筛选
  - assignee?: string      // 按指派人筛选
  - search?: string        // 搜索关键词

Response:
{
  tasks: Task[]
}
```

### 2.2 创建任务
**优先级：P0**

```
POST /api/tasks
Body:
{
  title: string;
  description?: string;
  priority: Priority;
  assigneeId?: string;
  tags?: string[];
  dueDate?: string;
}

Response:
{
  task: Task
}
```

### 2.3 更新任务
**优先级：P0**

```
PATCH /api/tasks/:id
Body:
{
  title?: string;
  description?: string;
  status?: TaskStatus;
  priority?: Priority;
  assigneeId?: string;
  tags?: string[];
  dueDate?: string;
}

Response:
{
  task: Task
}
```

### 2.4 移动任务
**优先级：P0**

```
POST /api/tasks/:id/move
Body:
{
  status: TaskStatus;
  position?: number;  // 新位置索引
}

Response:
{
  task: Task
}
```

### 2.5 删除任务
**优先级：P1**

```
DELETE /api/tasks/:id

Response:
{
  success: true
}
```

## 4. 业务规则

1. **状态流转限制**：
   - 任务可以从任意状态移动到任意状态
   - 移动到 "已完成" 状态时，自动更新 `updatedAt` 时间

2. **优先级排序**：
   - 同一列内，任务按优先级排序（critical > high > medium > low）
   - 相同优先级按创建时间排序

3. **标签限制**：
   - 每个任务最多 5 个标签
   - 标签长度不超过 20 字符

4. **删除限制**：
   - 已完成的任务才能删除（可选规则）
   - 删除操作需要二次确认
